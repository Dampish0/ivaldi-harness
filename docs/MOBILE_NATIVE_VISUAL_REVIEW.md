## Custom provider configuration, version 0.2.10

The form uses stacked Settings fields for provider ID, display name, base URL and credentials, with separate pages for API protocol, models and headers. The [native README](../experiments/mobile-native/README.md#custom-providers) records form lifetime and mutation ownership.

This feature requires an updated Ivaldi host with GET/PUT/DELETE `/api/provider/:id/editor`. Older hosts show an unavailable or upgrade state; the native client never falls back to the legacy replacement PUT. The [server editor](../packages/web/server/lib/opencode/DOCUMENTATION.md#revision-protected-custom-provider-editor) reads raw configuration layers and checks an opaque revision before saving or removing configuration. Edits keep the existing custom, project or user scope, unknown provider/options fields and extra fields on retained models. Advanced fields have no native controls. Config removal keeps stored credentials and other layers, which can reveal a lower-layer definition.

## Image attachments, version 0.2.4

The preceding build made attachments legible as file cards but still treated a picture like a filename. Users could neither check the selected image before sending nor inspect it in the conversation. That made the normal attach, review and send flow incomplete.

PNG, JPEG and WebP attachments now have thumbnails in the draft and conversation. The draft's attachment row animates in and out above the writing row, keeping attachment and send controls on their existing baseline. Thumbnails have press feedback and open a full-screen native preview with pinch, double-tap and button zoom, bounded panning, and a reset action. The image fits within the available area after rotation. Close and Android Back preserve the conversation and draft without focusing the editor. Loading and decode failure have explicit states, and failed previews can retry.

The implementation distinguishes picker-owned files from server file references. Local picker files and embedded raster data URLs can load directly. Server file paths, HTTP URLs, SVG and other unsupported references keep their file cards. A server path never becomes a phone-local read, even if an identically named file exists on the emulator. Authenticated remote image resolution and Markdown images remain work for the migration.
