# Ivaldi React Native mobile

The migration was approved on 12 September 2026 after the interaction comparison. This candidate is separately installed as `dev.ivaldi.nativecomparison`, displayed as Ivaldi Native. It connects to existing Ivaldi servers. The sample conversations and simulated response reducer have been removed.

## Ownership

This directory is outside the Bun workspaces and owns its npm lockfile and native dependencies. Desktop, web, VS Code and Capacitor do not import it. Keep the separate app identity until acceptance, credential transfer and release signing are complete.

`src/runtime/connection.ts` owns endpoint selection, identity probes, bearer headers, secure storage and HTTP lifetime. Import executable SDK code through `@opencode-ai/sdk/v2/client`; the package root also exports Node server code that Metro cannot bundle.

After successful pairing, the saved connection includes a SHA-256 digest of the normalized link. Startup uses that digest to recognize an Android launch intent replayed after Activity recreation. It restores the saved connection instead of redeeming the link twice. The link and its secret remain in memory; a different incoming link still requires confirmation.

`src/runtime/connection-identity.ts` allows re-pairing to reuse a saved local ID only after the probed server identity matches its existing pin and candidates overlap. An address reused by another server creates a separate saved connection. Legacy direct records without a saved pin remain reconnectable; re-pairing creates a separate record rather than merging credentials by URL. Existing reconnect and relay pin enforcement remains unchanged.

`src/runtime/connection-attempt.ts` owns connection preparation and activation. Manual connections, saved connections and startup restore share one synchronous attempt guard. Preparation may save newly issued credentials, but only the accepted attempt writes the active connection ID. Close or Cancel abandons network preparation; late success closes its runtime and late failure cannot overwrite the newer view. A cancelled single-use redemption may finish saving its issued credential as an inactive saved connection. The manager refreshes its saved list after completion. Close and Back briefly lock during the non-cancellable active-ID write. Incoming pairing links during that write remain available for confirmation after either outcome. Activation failure reports a storage failure.

`App` starts a fresh ChatScreen lifetime for each accepted runtime, including reconnecting to the same saved server. Old Settings operations cannot target its replacement. Chat hydration joins the existing storage queue so the preceding controller's final draft flush completes before the replacement reads its preferences.

`src/runtime/chat.ts` owns one runtime's sessions, models, agents, drafts, live status and mutations. It preserves loaded data on failure and reconciles history with events received during fetches. Server work continues when the app sleeps. An uncertain send retains its draft and message ID. Stop aborts the server session and checks that ID before releasing an unresolved send.

`src/runtime/chat-choices.ts` owns per-chat model and agent selection. Connection preferences retain a `sessionChoices` record. Migration associates the legacy model/agent pair with its saved active chat only. Visited chats keep their device selection. Otherwise native reads explicit session metadata, then the latest user-message choice. Missing evidence leaves a choice unset; new-chat defaults never fill an existing chat. A delayed defaults read cannot overwrite newer navigation or manual choices. During an explicit new-chat transition the composer temporarily stops accepting edits, so text cannot enter the preceding chat's draft.

`src/runtime/session-recovery.ts` distinguishes a missing selected chat from a failed lookup. Absence from a roots list is insufficient evidence; the session endpoint must return 404, or a live deletion event must confirm removal. Incomplete or failed list pagination leaves the preceding session list intact. Recovery creates a server chat without prompting and copies the current stranded draft into it. The original draft, attachments and regular new-chat draft remain stored. Navigation during recovery prevents the request from switching the selected chat. The recovery page scrolls with the measured composer and keyboard space.

`src/runtime/stream-response.ts` adapts decrypted relay streams to SDK response operations. React Native's global Response constructor cannot supply a streaming body. Request timeouts and abort listeners remain active until the body completes, fails or is cancelled.

`src/runtime/workspace.ts` prepares only the connected server's application HTML for the contained advanced-tools view. The runtime fetches it with its credential and adds a bootstrap before existing modules. Credentials stay out of URLs. The WebView uses an ephemeral session, restricts top-level navigation to the application path and exposes no native bridge. The existing file/editor, Changes, terminal, advanced Settings and integration implementations remain web-based during migration. This view requires a direct connection. Browser-local appearance preferences do not configure native chat; server session defaults use the shared settings contract described below.

`src/runtime/workspace-load.ts` owns one open workspace's request and WebView load state. Retry fetches fresh authenticated HTML and remounts the WebView. Request, main-document navigation and renderer-process failures expose Retry. Closing the view or replacing its runtime, session or mode invalidates old request and WebView callbacks. Late success cannot restore failed or closed content. Loading and failure keep the native Back control reachable; failure controls scroll at large text sizes.

`src/runtime/sidebar-disclosure.ts` owns project and archive disclosure for the mounted sidebar. A confirmed selected chat opens its ancestors once; an unresolved saved ID waits for its session record. Selecting another chat or changing its authoritative directory or archive membership opens its new location. Manual disclosure survives drawer close/reopen, metadata refresh and search hide/show. It resets with ChatScreen and is not persisted across app restarts. Folder accepts controlled disclosure for Sidebar. Message, tool and connection folders retain their local toggle behavior and animation.

`generate-portable.mts` copies the canonical pairing-v2 parser and encrypted relay client from shared UI and writes a source/hash manifest. Never edit generated portable files. Regenerate copies after shared changes and run the existing protocol tests. Native initialization installs WebCrypto before importing relay code.

`generate-assets.mts` extracts desktop themes, icon paths and all 11 language catalogs, including the full Settings dictionaries. Settings messages take precedence over core messages, matching shared i18n. Generation checks that every locale contains the English catalog's keys. Native counterparts use the local Button, Icon and i18n helpers. Selawik TTFs come from [Microsoft Selawik 1.01](https://github.com/microsoft/Selawik/releases/tag/1.01), the same release as the desktop font. Its license is in `assets/fonts/LICENSE.txt`.

## Native Settings and appearance

`src/components/SettingsScreen.tsx` owns full-screen Settings, its navigation stack, per-page scroll positions, save feedback and search over implemented destinations. General contains Mode. Appearance contains System/Light/Dark, interface font, text size and density. Chat contains message display preferences. Sessions contains default model, thinking and agent controls. Models and Providers opens provider setup. Language and Saved connections remain reachable from the root. Search opens its actual control page; opening Settings or navigating between pages dismisses the keyboard. Page transitions respect reduced motion. `src/components/SettingsControls.tsx` owns the shared native sections, navigation rows and checkbox rows used by these pages.

Opening Saved connections temporarily hides Settings while retaining its page, search, scroll positions and save feedback. Closing that manager returns to the same Settings context with the keyboard dismissed. Confirming a connection starts its fresh chat lifetime instead. Keyboard Controller suspension follows the Settings dialog's actual visibility, so the connection form can use its own keyboard handling while Settings remains logically open.

Settings owns keyboard avoidance inside its dialog. Landscape search temporarily hides the large page header and adds a keyboard-dismiss button without remounting the input or clearing its query. Root results and model results show their primary label while editing; secondary text, the header and the model reset row return when editing ends. Model/provider accessibility labels remain complete. Search results accept taps with the keyboard open. `SettingsForm` and `SettingsHeader` in `SettingsControls.tsx` provide the shared header, compact editing and focused-field scrolling used by provider authentication and the custom-provider editor. Done dismisses the keyboard; normal headers and field labels return afterward.

On Android, Settings waits for composer keyboard dismissal before suspending Keyboard Controller for its native dialog. React Native then applies status-bar style changes to the dialog as well as the Activity. Closing Settings restores the controller's prior state. The composer remains mounted and remeasures restored drafts or changed font metrics without replacing the editable input.

`src/runtime/appearance.ts` owns device preferences under `ivaldi.native.appearance.v1`. Defaults are System appearance, Selawik, 100 percent text size and 100 percent density. The interface font can be Selawik or the system font. Text size accepts 80 to 150 percent and density accepts 80 to 120 percent, both in steps of five. `ThemeProvider` and `useTypography` apply these preferences to native consumers alongside OS text scaling.

When the new storage key is absent, the store reads the legacy `ivaldi.native.theme` Light/Dark preference. It writes the new format on a changed preference, preserving fields the user did not edit. Invalid stored values or failed reads leave appearance controls unavailable until a successful retry. Writes run in order and publish new values only after storage succeeds. Failed writes preserve the last committed appearance. Settings retains the attempted operation for Retry, delays Saving feedback for 500 milliseconds and shows failures within the open page.

Work/Developer remains a per-connection preference owned by `src/runtime/chat.ts`. `preferencesReady` must be true before Mode can change. `setMode` persists the connection preferences before publishing the new mode, and rejects a failed write so Settings can offer Retry. Appearance and language are device preferences; they do not move into the connection store.

`src/components/SessionDefaultsPage.tsx` owns the Sessions summary, searchable model list, model-specific thinking choices and default agent selection. It receives the connected server's store and available native models and agents. Loading failure has its own Retry control. Writes use the Settings screen's delayed Saving indicator and retained Retry/cancel operation. Existing committed values remain visible after a failed refresh or save; unset defaults become selectable only after a successful load.

`src/runtime/session-defaults.ts` owns `SessionDefaultsStore`, its response schema and `resolveSessionDefaults`. `ChatScreen` supplies authenticated GET and PUT operations for `/api/config/settings` through the active native runtime. Each response is the complete settings object directly. The schema consumes only `defaultModel`, `defaultVariant` and `defaultAgent`, normalizing omitted strings to empty strings. The store sends changed fields only; an empty string clears a server default, while an omitted field leaves it unchanged. Clearing the model also clears its variant. Changing to another model clears the previous variant unless the change supplies a replacement. Reads and writes run in order, concurrent compatible reads share a request, and committed values come from the validated server response. A failed operation preserves the preceding committed snapshot. Keep the full settings response out of logs because unrelated settings may contain credentials.

These defaults belong to the connected Ivaldi server and are shared with its other clients. They are separate from device appearance and the native connection's current chat selection. New chat loads the server defaults before applying its initial selection through the chat controller. A failed load retains the current conversation and exposes Retry/cancel. Available saved choices take effect; unavailable saved IDs remain stored and visible while the resolver chooses a usable native fallback. Model IDs containing slashes retain their complete identity. Changing server defaults does not reconfigure an existing conversation. Project-specific defaults and the full web agent/config fallback precedence remain outside this native slice.

Native pages for agent configuration, projects, MCP, plugins, skills and other server configuration remain migration work. Provider setup and supported custom-provider editing are described below. Quota details and advanced provider fields outside the editor remain in the retained web tools. The [comparison document](../../docs/MOBILE_CAPACITOR_NATIVE_PARITY.md) keeps the original gaps and the [visual review](../../docs/MOBILE_NATIVE_VISUAL_REVIEW.md) records build validation and remaining acceptance limits.

`src/runtime/chat-display.ts` owns device preferences under `ivaldi.native.chat-display.v1`. The defaults preserve the preceding native behavior: reasoning is visible and collapsible, user messages use plain text, code scrolls horizontally, and tools start closed. `ChatDisplayProvider` survives runtime changes. Reads validate the complete saved snapshot; missing storage uses defaults, while invalid data and read failures leave controls unavailable until Retry succeeds. Writes serialize and publish only after storage succeeds. A failed write retains the preceding values and uses the existing Settings Retry/cancel feedback. These preferences do not change server configuration or the retained web app.

`ChatDisplayPage` groups reasoning visibility, reasoning disclosure, user-message Markdown, code wrapping and Bash/edit tool expansion. Settings search indexes these controls and scrolls to their section, with conditional reasoning availability matching the page. `MessageRow` applies them to existing and incoming messages. Tool families follow the shared chat aliases. A changed expansion default resets only the affected tool disclosure; unrelated preference changes retain manual disclosure state. Neither reasoning visibility nor display formatting changes stored or transmitted messages. Code copying retains the original text in either wrapping mode.

### Provider setup

`src/components/ProviderSettings.tsx` owns provider search, connection details, API-key entry, OAuth prompts and model visibility. `src/runtime/providers.ts` owns one connected runtime's catalog, auth methods, source metadata and pending Apply state. Catalog and method reads use SDK v2; schemas retain display fields and discard provider keys, options and source paths. Source reads use the current chat directory or new-chat draft directory. Directory changes invalidate old reads and OAuth work. Native Settings has no independent project-scope selector.

API keys go through SDK `auth.set`; OAuth uses the declared method's original array index with text/select prompts and `eq`/`neq` conditions. Only visible prompt answers are submitted. A failed auth-method read exposes Retry; it cannot silently enable an API form. A successfully loaded empty method list retains the server's API-key fallback. API keys, prompt answers and callback codes remain in transient form/request memory and are excluded from store snapshots, persistence and error messages.

OAuth supports server-reported `auto` and `code` completion. An HTTP/S authorization URL is available through Open; instructions-only responses also work. Auto completion waits on the callback request, while code completion requires an explicit submit. Leaving the form, cancelling or disposing the runtime aborts OAuth work. `NativeRuntime` allows five minutes specifically for POST `/api/provider/:id/oauth/callback`; ordinary non-streaming requests retain their 30-second timeout. Caller cancellation and runtime disposal still abort that longer request. The `claude-code` host CLI flow follows its instructions without opening its localhost callback on the phone, and refreshes models after completion without requiring a server restart. Native UI does not remove host CLI credentials.

Saving credentials changes the server's auth store. Confirmed removal uses only DELETE `/api/provider/:id/auth?scope=auth`, after source metadata confirms stored auth. Environment and configuration credentials remain. Successful mutations stay successful if the subsequent source refresh fails; that read has its own Retry. Catalog, method and source failures retain preceding data while displaying failure, and source failure disables removal. Pending credential changes remain in the runtime's in-memory Apply state; the credentials themselves are stored by the server.

Apply requires confirmation before POST `/api/config/reload`. A managed restart honors the server's reload delay, then refreshes provider metadata and chat models. If refresh fails after restart, Retry repeats the reads without another restart. An external server's `requiresManualRestart` response preserves the pending state and displays manual restart guidance. The localized "I've restarted the server" action calls `confirmManualRestart()` to refresh provider metadata and `ChatController` models without another reload request. Only a successful refresh clears the manual state; failure retains the guidance, and credentials saved during the refresh remain pending. Custom-provider configuration changes use this same Apply owner.

`src/runtime/model-visibility.ts` owns device preferences under `ivaldi.native.model-visibility.v1`. Hidden IDs use the full `providerID/modelID` key. `App` retains this store across connections. Per-model and provider-wide show/hide writes serialize and publish only after storage succeeds; failed writes retain the committed list. Invalid storage or read failure leaves visibility controls unavailable until Retry. Both chat model search/favorites and Sessions' default-model picker filter hidden IDs. Hiding a model preserves favorites, the current chat's model and agent, and saved server defaults. It does not disable a server model.

`ChatController.refreshModels()` delegates to `src/runtime/model-refresh.ts`. Refresh requests run in order, so a request made after Apply cannot reuse a pre-restart read. Model and agent requests settle independently: a successful result remains usable when the other fails. Refresh updates catalogs without replacing the selected chat, draft, model or agent, including choices changed while a read was pending. Initial startup may choose a fallback only for an unchanged new-chat selection. Disposing the controller prevents late reads from publishing.

### Custom providers

`src/components/CustomProviderSettings.tsx` owns the create/edit form, protocol selection, model and header detail pages, field errors and unsaved-edit confirmation. It supports OpenAI Chat Completions, OpenAI Responses and Anthropic Messages adapters, a base URL, model IDs/names, headers, and either a literal API key or `{env:NAME}`. Add custom provider is reachable from Models and Providers; a configured provider's details expose editing. Provider IDs remain fixed while editing. `SettingsForm` and `SettingsHeader` keep these nested pages consistent with provider authentication.

`src/runtime/custom-providers.ts` owns validation, editor reads and guarded mutations. The connected host must implement GET/PUT/DELETE `/api/provider/:id/editor`; an older host or unsupported runtime exposes an explicit upgrade/unavailable state. Native never falls back to the legacy replacement PUT. The [server provider editor](../../packages/web/server/lib/opencode/DOCUMENTATION.md#public-exports-providersjs) owns raw-layer projection, revision checks and preservation. Unsupported adapter or configuration shapes leave editing unavailable instead of decoding them into a lossy form. Creation targets user configuration and requires an unused config/catalog ID. Editing targets the winning custom, project or user layer for the captured chat directory. Native has no independent Settings project selector or config-layer picker.

Editor responses contain only supported editable fields and credential-presence flags. Existing inline API keys are omitted. Header values and form/request credentials remain transient in the editor; observable runtime snapshots contain only safe failure metadata. The parser preserves dictionary keys such as `__proto__` through validated entries. Blank edit credentials preserve the complete existing environment list and inline key. Explicit stored-auth or environment modes replace that credential selection. The server retains unrelated provider/options fields and extra fields on retained models; removing a model row explicitly removes that model. Advanced fields remain preserved but have no native controls.

Save validates ID, name, URL and model/header rows before network work and rechecks the editor revision before SDK `auth.set`. Create defers only the credential-required check until the authoritative editor response confirms stored auth, inline credentials or environment names. This permits blank-key recovery after a prior key saved but config did not, including after a cold launch; a failed read or confirmed absence cannot authorize the write. `hasPendingCredential(providerID)` exposes only credential-presence metadata for the current directory so reopening an in-memory partial create can retain its retry behavior.

The guarded config PUT follows an accepted key write. These two operations are not atomic. If credentials save but config fails, pending Apply remains and the editor reports partial success. Retrying the same revision uses the accepted key without writing it again. A conflict after key acceptance has distinct Reload guidance; a changed revision is never adopted silently. There is no automatic credential rollback. A failed or lost response cannot establish that the server made no change. Reads can retry, while config mutations remain revision-protected and uncertain key outcomes must not be described as rolled back.

Confirmed removal uses the editor's exact config scope and revision. Stored auth and other layers remain, so removing a higher layer may reveal another provider definition. A failed delete keeps the editor available for retry or conflict reload. `ProvidersStore.configurationChange()` shares the mutation lock with sign-in and Apply and records accepted config/auth changes. Runtime or directory replacement prevents an unfinished save from issuing its next request against another owner; disposing a read prevents its form values from reaching a replacement editor. Installed acceptance for this 0.2.10 work is recorded separately in the visual review.

## Build on Windows

Install this directory independently with `npm ci --workspaces=false`. Run `npm run assets:generate` from this directory after changing a consumed theme, icon or label. The repository dependencies provide the asset generator's TypeScript runner.

The first Windows build failed because native C++ paths exceeded Ninja's limit. Junctions and a drive alias still resolved to the original paths inside Expo autolinking. Stage a physical copy before building:

```powershell
node scripts/stage-windows.mjs
Set-Location "$env:USERPROFILE/ivaldi-native-build"
npm ci --workspaces=false
$env:JAVA_HOME = 'C:/Program Files/Android/Android Studio/jbr'
$env:ANDROID_HOME = "$env:LOCALAPPDATA/Android/Sdk"
$env:CI = '1'
$env:EXPO_NO_GIT_STATUS = '1'
node node_modules/expo/bin/cli prebuild --platform android --no-install
./android/gradlew.bat -p android :app:assembleRelease '-PreactNativeArchitectures=arm64-v8a,x86_64' --max-workers=4
```

This creates an arm64/x86_64 release-mode APK with the generated local debug signing key. It is a local acceptance build, not an app-store release. It includes its JS bundle and runs without Metro or an Expo account. The experiment has its own app ID. Never uninstall the user's existing `dev.ivaldi.mobile` app to install this one.

## Implementation choices

- [Keyboard Controller](https://kirillzyusko.github.io/react-native-keyboard-controller/docs/api/components/keyboard-sticky-view) moves the composer from native keyboard progress. Attachment and send controls share a bottom baseline around a single writing row. Model selection lives in the chat header. The editor remains a single native TextInput through resizing and picker handoff. A multiline draft retains its height after blur, up to a limit that scales with text size and available keyboard space. Longer content scrolls within the input.
- [KeyboardChatScrollView](https://kirillzyusko.github.io/react-native-keyboard-controller/docs/api/components/keyboard-chat-scroll-view) handles keyboard movement and extra composer padding. `whenAtEnd` avoids lifting a user reading older messages.
- Reanimated handles drawer and sheet translation, backdrop opacity, and short disclosure geometry changes. Gesture Handler updates drag position on the UI thread. Interrupted movement continues from its current value.
- Opening the sidebar dismisses the composer keyboard. Only an explicit search action focuses sidebar search.
- The composer fades while navigation covers it, so a sheet's search keyboard cannot expose a second writing bar behind that sheet. New chat is available in the sidebar and the chat actions menu. Short action sheets use less height and animate to the larger picker height when navigating onward.
- Conversation navigation uses Keyboard Controller's end-visibility callback. A floating button returns to the latest reply, clears the reader's manual-scroll intent and follows the measured composer and keyboard. Its space check uses the containing view's layout and hides the control when it cannot fit below the top safe area. Ordinary streaming preserves a reader's position in older content.
- Code blocks keep their language and copy action outside the horizontal code scroller. Message and code copying share a native clipboard action with explicit success/failure feedback and unmount cleanup. Attachment cards show filenames and file types.
- `runtime/images.ts` classifies previewable PNG, JPEG and WebP sources by provenance. Picker-owned local files and embedded raster data URLs can become native images. Server `file://` paths, HTTP URLs and unsupported formats remain file cards. They never trigger phone-local file reads or unauthenticated image requests. Remote and Markdown image resolution remain migration work.
- Draft thumbnails reserve an animated attachment row above the editor. Opening a thumbnail dismisses the keyboard without replacing the editor or changing its draft. `ImagePreview` owns a full-screen native modal, loading/error recovery, safe-area layout, bounded pinch/pan and double-tap zoom. Zoom controls use the same desktop icons and labels. Rotation resets the image to fit; Back and close return without focusing the composer. The modal unmounts when the session or runtime changes, and underlying chat controls are hidden from accessibility while it is open.
- The response footer distinguishes live work from server retry status. Its dot animates only while the footer is at the conversation end and navigation is closed. Pending permission/question cards take precedence over the work indicator. Copy and send/stop icons crossfade inside fixed icon bounds.
- The attachment picker starts after the keyboard closes and the editor reaches its draft height on the UI thread. Android's keyboard-hidden notification alone does not guarantee those updates have reached the view.
- Sheets reserve the bottom safe area and shrink above the keyboard. Landscape model search uses a compact header; native inputs disable Android's full-screen text extraction. Chat headers and empty-state text make room during landscape keyboard movement.
- `ChatScreen` owns the model picker's nested effort destination. Android Back and the visible Back action return to the preserved model list before closing the sheet. `ModelPicker` keeps both pages mounted and moves them with one reversible transform/opacity transition that respects reduced motion. The covered page cannot receive touch or accessibility focus.
- The composer background spans the screen even when the writing controls reach their maximum width. This prevents conversation text from showing through in the side gutters during landscape keyboard use.
- `reanimated.staticFeatureFlags.FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS` is disabled. The default optimization restored stale composer geometry after Android's document activity returned, despite correct focus and shared values. See [upstream Android resume reproduction](https://github.com/software-mansion/react-native-reanimated/issues/9574). This build setting requires a native rebuild. Disabling it keeps more animated styles in Reanimated's registry, so measure large lists before release. Re-enable only after a dependency fix passes repeated picker and background/resume checks.
- Drafts, active conversation, project target, Work/Developer, model, agent and favorites persist per connection. Language and appearance are device preferences. Writes are serialized and flushed when backgrounded.
- Bearer credentials use the OS secure store. Pairing secrets remain in memory and require explicit confirmation before redemption.

## Emulator testing

The Android 35 virtual device is `IvaldiReleaseQa`, ADB serial `emulator-5554`. The APK above includes x86_64 so it runs there without the phone. Start the emulator hidden with `Start-Process -WindowStyle Hidden` and its `-no-window` option. Do not reset existing emulator data.

`scripts/phone.mjs` now defaults to the emulator. Set ANDROID_SERIAL explicitly to test a physical device. It checks that Ivaldi Native is foreground before operating the UI. Screenshots go into `artifacts` relative to the command's working directory.

`node scripts/qa-server.mjs --images` adds a synthetic raster image, an invalid image and a server file URL to the visual fixture. The checked-in image is synthetic and can also be pushed to Android Downloads to exercise the document picker. The phone helper rejects history attachment taps whose center is behind the composer. Inspect bounds before gestures; the helper cannot establish every native view's drawing order from an accessibility tree.

`node scripts/qa-server.mjs` starts a loopback-only fixture and opens a pairing confirmation in the emulator. Credentials remain in process memory. It exercises the real native adapter and SDK with deterministic streaming, permissions and questions. Its stats endpoint contains only synthetic test results. The fixture is never bundled into the application. End the fixture process after testing.

Use `--port=39125` for a second independent fixture. Its pairing label includes the port, which lets cancellation and cold-start checks distinguish the active server from a newly saved inactive connection. Both listeners and ADB forwards remain local.

Add `--visual` for long names, 24 models, formatted message content, an attachment card and nested project archives. Its loopback-only `/__qa/status` endpoint accepts a POST with `type` set to `busy`, `retry` or `idle` to exercise response feedback without calling a model. The [visual review](../../docs/MOBILE_NATIVE_VISUAL_REVIEW.md) records reproduced layout defects, changes and emulator evidence.

Add `--chat-display` for the visual fixture plus a formatted user message and separate Bash, shell, edit and apply_patch results. The ordinary read tool remains present so expansion preferences can be checked against an unaffected tool family.

The fixture implements authenticated GET/PUT `/api/config/settings` and GET `/api/session/:id`. Initial defaults are `qa/native`, `high` and `build`. Seeded sessions carry those model/variant/agent choices. Creation validates and uses explicit requested choices, and prompted user messages record the resolved choices in their SDK-shaped metadata. Settings writes merge the three default fields, omit cleared values and preserve the unrelated `showReasoning` marker. An authenticated `/mobile` HTML fixture displays its session and mode and performs a second authenticated request without displaying credentials. These loopback controls exercise recovery and cancellation:

| Route | Request and behavior |
| --- | --- |
| POST `/__qa/fail-next` | Set `operation` to `settings-read`, `settings-write`, `session-get`, `session-create`, `workspace-load`, `auth-session` or `pairing-redeem`. Optional `status` is 500 or 503, defaulting to 503; session-get also accepts 404. The next matching request consumes the failure once. Pairing and auth checks retain their existing authentication rules. |
| POST `/__qa/delay-next` | Use the same `operation` names and an integer `delayMs` from 1 to 5000. The next authenticated matching request consumes the delay once. A separately armed failure applies after that delay. |
| POST `/__qa/delete-session` | Supply a fixture `sessionId`. It removes that synthetic session, history and timers and emits `session.deleted`. Set `emitEvent: false` to exercise a cold restore without a live deletion event. |
| GET `/__qa/stats` | Includes current safe default fields, the preservation marker, pending failures and delays, the latest prompt's model/variant/agent and the last deleted fixture session. Read/get/create counters count attempts; `settingsWrites` counts successful writes. `workspaceLoads` counts authenticated HTML requests, `workspaceChecks` counts authenticated requests made by its page, and `authChecks` counts session-authentication checks. Prompt text and credentials are excluded. |

Add `--providers` to exercise native provider setup. `scripts/fixtures/native-providers.mjs` adds disconnected `qa-api` and `qa-oauth` providers while preserving the existing `qa` models. It accepts only synthetic input: API key `native-qa-key`; OAuth account `personal`, or `team` with workspace `native-qa-team`; code-flow answer `native-qa-code`. OAuth methods retain indexes 1 for auto and 2 for code, after API method 0. The loopback `/__qa/provider-login` page contains no credentials or external service integration. Completing the synthetic callback does not prove a real provider sign-in works.

Provider tests use these additional loopback controls:

| Route | Request and behavior |
| --- | --- |
| POST `/__qa/fail-next` or `/__qa/delay-next` | Also accepts `provider-list`, `provider-auth`, `provider-source`, `provider-save`, `provider-delete`, `provider-authorize`, `provider-callback` and `provider-reload`. Existing status/delay bounds apply. |
| POST `/__qa/providers` | Set `reloadMode` to `managed` or `manual`. Managed Apply updates active provider IDs; manual Apply returns `requiresManualRestart` and retains the old catalog. Add `simulateRestart: true` to explicitly apply stored state during a manual-restart test. |
| GET `/__qa/stats` | Adds `providers` with request counters, stored and connected provider IDs, reload mode and pending OAuth method index. Submitted keys, codes and prompt values are discarded. |

Run `node --test scripts/fixtures/native-providers.test.mjs` from this directory for SDK-based HTTP fixture checks. Native store tests remain part of `npm test`. Device sign-in, keyboard and navigation acceptance require an installed build separately.

The phone helper rejects failed UIAutomator captures instead of reading the preceding XML file. Android can fail its idle check while a continuous animation is visible; use a screenshot for that state. Its attribute reader supports both XML quote styles, so copied code containing quotes and newlines remains inspectable.

Run `npm test` and `npm run type-check` here. Run repository oxlint and ESLint on authored native code. Inspect `bun run dead-code` when files or imports change. Shared transport changes also require root workspace checks and focused relay tests.

## Acceptance

Add `--relay` to the fixture command to run native requests through the production encrypted host handshake and tunnel dispatcher. Its HTTP and WebSocket ports are forwarded only to the emulator. Restarting the fixture invalidates its ephemeral credentials, so confirm its new pairing link before continuing.

Record the same phone, keyboard and actions for the existing app and the native comparison.
